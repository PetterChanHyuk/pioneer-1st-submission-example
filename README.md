# NH선물 REST API Pioneer 1기 · 제출 예시

팀 GitHub 저장소를 어떻게 꾸리고 주차별 결과물을 어떻게 올리는지 보여주는 **운영 담당자의 예시 저장소**입니다.
참가팀 공용 제출함이 아닙니다. 각 팀은 자신의 저장소를 만들고 팀 Discord 방에 링크를 올립니다.

**활동 기간:** 2026.10.21 \~ 2026.12.11
**과제 제출:** 매주 금요일 23:59 까지 (마감 전 마지막 커밋이 제출본)

## 저장소 구조

**주차 폴더 하나 = README.md(보고서) + 코드 파일 + `results/`·`screenshots/`** 입니다.

```
weekNN/
  README.md       그 주차의 보고서 — 과제·실행 방법·전략·사용 API·결과·분석·오류·개선
  (코드 파일)      프로그램 코드와 설정 파일
  results/        실행 근거 원본 데이터 (JSON·CSV·로그 등)
  screenshots/    실제 화면 캡처 (README 본문에 이미지로 넣음)
```

주차마다 Markdown 문서는 README.md 하나만 둡니다. 보고서·실행 방법·캡처 설명을 모두 그 안에 씁니다.
실제 예는 [week02](week02/README.md)를 보세요.

**중간 발표(11/13)** 에서는 2\~4주차 과제 중 하나를 골라 PPT 로 발표합니다.

## 기록 시 주의사항

- **인증정보를 올리지 않습니다.** APP Key, Secret Key, 토큰, 계좌번호·비밀번호와 개인 설정 파일은 저장소에 넣지 않습니다. 화면과 로그의 계좌 식별정보·개인정보는 가립니다.
- **실행 환경을 구분합니다.** 앱 내부 시뮬레이션, 모의계좌 주문, 실전 기록을 섞지 않고 어느 것인지 적습니다. 시뮬레이션 체결을 모의계좌 체결로 쓰지 않습니다.
- **꾸미지 않습니다.** 주문 접수와 실제 체결을 구분하고, 실행하지 않은 수치나 성공 여부를 만들지 않습니다. 손실 결과도 그대로 적고 분석합니다.
